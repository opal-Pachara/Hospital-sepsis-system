## คำนำ

การจัดทำคู่มือการใช้งานระบบแจ้งเตือนภาวะติดเชื้อในกระแสเลือดแบบเรียลไทม์ (Real-Time Sepsis Alert System: RTSAS) ฉบับสมบูรณ์นี้ มีวัตถุประสงค์หลักเพื่อเป็นคู่มือมาตรฐานการปฏิบัติงานทางคลินิก (Clinical Standard Operating Procedures: SOP) และเอกสารอ้างอิงขั้นตอนการใช้งานระบบคอมพิวเตอร์อย่างละเอียดสำหรับแพทย์ พยาบาลวิชาชีพ เภสัชกร และบุคลากรทางการแพทย์ทุกระดับ เพื่อให้การประเมิน วินิจฉัย และการรักษาผู้ป่วยที่มีภาวะติดเชื้อในกระแสเลือด (Sepsis) เป็นไปอย่างถูกต้อง แม่นยำ และรวดเร็วตามเกณฑ์เวลาวิกฤต Golden Hour

ระบบ RTSAS เป็นนวัตกรรมเว็บแอปพลิเคชันทางการแพทย์ที่พัฒนาขึ้นตามหลักการยศาสตร์คลินิก (Clinical Ergonomics) เชื่อมโยงข้อมูลเวชระเบียนผู้ป่วยแบบเรียลไทม์จากฐานข้อมูลโรงพยาบาล HOSxP MySQL ทำการประมวลผลสัญญาณชีพและคำนวณคะแนนเตือนภัยล่วงหน้า (National Early Warning Score 2: NEWS 2) โดยอัตโนมัติ พร้อมระบบแจ้งเตือนฉุกเฉินทันทีเมื่อตรวจพบผู้ป่วยวิกฤต (คะแนน NEWS ≥ 5) ระบบมีการจัดลำดับคิวแจ้งเตือนหลายรายพร้อมกัน (Multi-Alert Queue), นาฬิกานับถอยหลังการให้ยาปฏิชีวนะภายใน 60 นาที (1-Hour Sepsis Bundle Countdown), ตารางติดตามสัญญาณชีพซ้ำทุก 15 นาที 4 รอบแรก และทุก 30 นาทีในรอบถัดไป (Q15/Q30 Reassessment Schedule), ระบบบันทึกไทม์ไลน์คลินิกระดับวินาทีที่สามารถคัดลอกลงระบบ HOSxP ได้ 100% โดยไม่ต้องพิมพ์ซ้ำ ตลอดจนศูนย์ตรวจสอบบันทึกเหตุการณ์ระบบ (System Logs Viewer) และชุดเครื่องมือทดสอบสำหรับผู้ดูแลระบบ IT (IT Admin Suite)

## บทที่ 1: สถาปัตยกรรมระบบ บทบาทผู้ใช้งาน และการยืนยันตัวตน

### 1.1 ภาพรวมสถาปัตยกรรมระบบ RTSAS
ระบบ RTSAS เชื่อมต่อกับฐานข้อมูล HOSxP MySQL Connection Pool ของโรงพยาบาลบางคล้า เพื่อดึงข้อมูลสัญญาณชีพผู้ป่วยนอกและผู้ป่วยห้องฉุกเฉินมาคำนวณคะแนนเตือนภัยล่วงหน้า (NEWS 2) แบบเรียลไทม์ โดยใช้การคิวรีแบบ Read-Only และมี In-Memory Cache ร่วมกับฐานข้อมูล SQLite ในเครื่องเพื่อรับประกันความพร้อมใช้งานสูง (High Availability: HA)

> 🔒 **มาตรฐานความปลอดภัยข้อมูลสุขภาพ (PDPA):** ข้อมูลรหัสประจำตัวผู้ป่วย (HN) ที่แสดงผลบนหน้าจอทุกจุดจะถูกปิดบังตัวเลข 4 หลักกลางเสมอ (เช่น `HN****0187`) เพื่อป้องกันการเปิดเผยข้อมูลส่วนบุคคลในพื้นที่บริการ

### 1.2 โครงสร้างบทบาทผู้ใช้งาน (Role-Based Access Control: RBAC)
1. **แพทย์ (Doctor - 🩺):** วินิจฉัยและยืนยันภาวะติดเชื้อ (Doctor Confirmation), ปฏิเสธว่าไม่ใช่การติดเชื้อ (Rule Out Sepsis), สั่งยาปฏิชีวนะตัวที่ 2 และสายสวนปัสสาวะ, กดยืนยันสิ้นสุดการรักษา (Treatment Complete)
2. **พยาบาล (Nurse - 💉):** ปฏิบัติการพยาบาลตาม 1-Hour Sepsis Bundle, บันทึกการเจาะเลือด/สารน้ำ/ยา, บันทึกสัญญาณชีพซ้ำทุก 15 นาที 4 รอบแรก และทุก 30 นาทีในรอบถัดไป, จัดการกระดิ่งเตือน, คัดลอก Nursing Note ลง HOSxP
3. **เจ้าหน้าที่ IT (IT Admin - 💻):** ตรวจสอบสถานะการเชื่อมต่อ MySQL Connection Pool, มอนิเตอร์และล้างหน่วยความจำแคช (Safe Sepsis Guard), ตรวจสอบ System Logs, ทดสอบ Database Failover, จัดการบัญชีผู้ใช้งาน

| ฟังก์ชันงานในระบบ | แพทย์ (Doctor) | พยาบาล (Nurse) | เจ้าหน้าที่ IT (IT Admin) |
| :--- | :---: | :---: | :---: |
| วินิจฉัยยืนยัน Sepsis / Rule Out Sepsis | ✅ ดำเนินการได้ (สิทธิ์เฉพาะ) | ❌ ดูได้อย่างเดียว | ❌ ไม่มีสิทธิ์ |
| ปฏิบัติการ Sepsis Bundle Checklist | ✅ กำกับและตรวจสอบ | ✅ บันทึกและข้ามขั้นตอน | ❌ ไม่มีสิทธิ์ |
| บันทึกสัญญาณชีพซ้ำ (Q15 / Q30 Reassessment) | ✅ ดูคะแนน Live NEWS | ✅ บันทึกค่าสัญญาณชีพ | ❌ ไม่มีสิทธิ์ |
| กดยืนยันสิ้นสุดการรักษา (Treatment Complete) | ✅ สั่งการและยืนยัน | ✅ บันทึกตามคำสั่งแพทย์ | ❌ ไม่มีสิทธิ์ |
| คัดลอก Nursing Note เพื่อนำไปวางใน HOSxP | ✅ คัดลอกได้ | ✅ คัดลอกได้ (หน้าที่หลัก) | ❌ ไม่มีสิทธิ์ |
| เปิดดูแดชบอร์ดสถิติผู้ป่วยที่รักษาแล้ว (Treated) | ✅ เข้าถึงได้ | ✅ เข้าถึงได้ | ✅ เข้าถึงได้ |
| เปิดดูบันทึกเหตุการณ์ระบบ (System Logs Modal) | ✅ เปิดดูได้ | ✅ เปิดดูได้ | ✅ เปิดดูและล้าง Logs ได้ |
| เข้าใช้งานศูนย์ควบคุมระบบ (IT Admin Panel) | ❌ ไม่มีสิทธิ์ | ❌ ไม่มีสิทธิ์ | ✅ เข้าถึงได้ (สิทธิ์เฉพาะ) |
| ทดสอบตัด/ต่อฐานข้อมูลจริง (Failover Tester) | ❌ ไม่มีสิทธิ์ | ❌ ไม่มีสิทธิ์ | ✅ ดำเนินการได้ |
| จำลองผู้ป่วย / จำลองการแจ้งเตือน (Simulators) | ❌ ไม่มีสิทธิ์ | ❌ ไม่มีสิทธิ์ | ✅ ทดสอบระบบได้ |

## บทที่ 2: ระบบแจ้งเตือนฉุกเฉินและป๊อปอัปวิกฤต

### 2.1 ตรรกะการตรวจจับผู้ป่วยวิกฤต (NEWS ≥ 5 Trigger)
ระบบตรวจจับคะแนน NEWS อัตโนมัติ หากคะแนนรวม ≥ 5 หรือสัญญาณชีพตัวใดตัวหนึ่งได้แต้ม 3 คะแนน ระบบจะยิงหน้าต่างแจ้งเตือนฉุกเฉินทันที

### 2.2 หน้าต่างแจ้งเตือนเดี่ยว (Single Sepsis Alert Modal)
แสดงหน้าต่างสีแดงสะดุดตา พร้อมข้อมูลสรุปผู้ป่วย สัญญาณชีพแรกรับ และปุ่มสีแดง **"รับทราบและเริ่มการรักษาทันที"**

### 2.3 หน้าต่างคิวแจ้งเตือนหลายรายพร้อมกัน (Multi-Alert Queue Modal)
เมื่อมีผู้ป่วยวิกฤตเข้ามาพร้อมกันหลายราย ระบบจะจัดเรียงตามลำดับความรุนแรงของคะแนน NEWS และแสดงหน้าต่างคิว ให้บุคลากรกดรับทราบทีละรายอย่างเป็นระบบ

### 2.4 กลไก Smart Dismissal Guard และระบบเสียงไซเรน
ป้องกันการเตือนซ้ำซ้อนสำหรับเคสที่รับทราบไปแล้ว และส่งเสียงไซเรนเตือนภัยความถี่สูงผ่าน Web Audio API โดยสามารถคลิกเปิด/ปิดเสียงได้บน Header Bar

## บทที่ 3: ภาพรวมหน้าจอหลักและการยศาสตร์คลินิก

ระบบจัดวางหน้าจอแบบ 3 คอลัมน์ (Left Sidebar, Center Workflow, Right Detail Panel):
1. **คอลัมน์ซ้าย (Sidebar Queue):** คิวผู้ป่วยในห้องฉุกเฉิน, ตัวกรอง 3 โหมด, ชิปคะแนน NEWS, มินินับถอยหลัง, และปุ่มดึงข้อมูล HOSxP
2. **คอลัมน์กลาง (Workflow & Checklist):** ศูนย์กลางกู้ชีพ Sepsis Bundle 4 ระยะ, ปุ่มตัดสินใจของแพทย์ (Phase 2), และตาราง Reassessment (Phase 4)
3. **คอลัมน์ขวา (Patient Detail & Audit):** ข้อมูลผู้ป่วย, อาการสำคัญ (Chief Complaint) ตัดคำอัตโนมัติ, ตารางสัญญาณชีพ 6 ค่า, แผงคิดคะแนน NEWS 2, และไทม์ไลน์คลินิก

## บทที่ 4: การคัดแยกและการจัดการคิวผู้ป่วยในแผนก

- **3 ตัวกรอง:** "กำลังรักษา" (Active), "🔴 เสี่ยง" (NEWS ≥ 5), "✅ รักษาแล้ว" (Treated Dashboard)
- **การ์ดผู้ป่วย (Patient Card):** แสดง Masked HN, เพศ, อายุ, ป้ายเตือนความเสี่ยง, คะแนน NEWS, เวลามาถึง, และมินินับถอยหลัง `⏱️ 42:09 Sepsis Bundle`
- **ปุ่มดึงข้อมูล (Manual Pull):** สั่งดึงข้อมูลล่าสุดจาก HOSxP ทันที

## บทที่ 5: แผงข้อมูลผู้ป่วย สัญญาณชีพ และการคำนวณคะแนน NEWS

- **Patient Info Bar:** Masked HN, VN, เวลาคัดกรอง, เวลาใน ER นับเดินหน้าวินาทีต่อวินาที
- **Chief Complaint Box:** ระบบตัดคำภาษาไทยอัตโนมัติ (Responsive Text Wrap) ไม่ล้นจอ
- **ตารางสัญญาณชีพ 6 ค่า:** RR, SpO2, Temp, SBP/DBP, HR, GCS/AVPU พร้อมแต้มคะแนนย่อย
- **NEWS 2 Logic Panel:** แจกแจงสูตรคะแนนรวมตามเกณฑ์ RCP 2017 อย่างโปร่งใส

## บทที่ 6: กระบวนการกู้ชีพ Sepsis Bundle — 4 ระยะการรักษา

1. **Phase 1 (Initial Response):** รับทราบและแจ้งแพทย์เวร
2. **Phase 2 (Doctor Decision):** 
   - ปุ่มแดง "🔴 ยืนยัน — ติดเชื้อ" -> เริ่มนับถอยหลัง 60 นาที, ปลดล็อก Phase 3
   - ปุ่มเขียว "🟢 ไม่ยืนยัน — Rule Out Sepsis" -> ยุติกระบวนการ, ย้ายไป Treated Dashboard
3. **Phase 3 (Hour-1 Sepsis Bundle):**
   - Hemoculture 2 ขวด (บังคับระบุ Anatomical Puncture Site)
   - IV Fluid (บังคับระบุชนิดและอัตราหยด)
   - IV Antibiotic ตัวที่ 1 (ภายใน 60 นาที)
   - **Clinical Skip Logic:** ปุ่ม "⏭ ข้ามขั้นตอนนี้" สำหรับยาตัวที่ 2 และ Foley Cath เมื่อไม่มีข้อบ่งชี้
4. **Countdown Banner:** นับถอยหลัง 60 นาที และแสดงสีแดงติดลบเตือนเมื่อ Overdue

## บทที่ 7: ระบบการติดตามสัญญาณชีพซ้ำตามรอบเวลา

- **ตารางรอบเวลา:** Q15 x 4 รอบแรก (นาทีที่ 15, 30, 45, 60) และ Q30 ในรอบถัดไป (นาทีที่ 90, 120...)
- **Assessment Form Modal:** กรอกสัญญาณชีพ 6 ค่า, แปลง GCS เป็น AVPU อัตโนมัติ, Live NEWS Score Preview, ปุ่มทางลัด "✅ รักษาเสร็จแล้ว"
- **Reminder Modal:** กระดิ่งเตือนเมื่อถึงกำหนดรอบเวลา พร้อมปุ่มบันทึกด่วนและปุ่มเลื่อนการเตือน (Snooze)

## บทที่ 8: การสิ้นสุดการรักษาและการส่งต่อ

- กดยืนยันสิ้นสุดการรักษาได้จากปุ่มใหญ่ด้านล่าง Checklist หรือภายใน Assessment Form Modal
- หน้าต่าง In-App Confirmation Modal ยืนยันความถูกต้อง
- เมื่อยืนยันแล้ว: นาฬิกาหยุดเดิน, แสดง Green Banner, ล็อกข้อมูลเป็น Read-Only, ย้ายเคสไป Treated Dashboard

## บทที่ 9: แผงไทม์ไลน์คลินิกและการส่งออกข้อมูลสู่ระบบ HIS

- **Clinical Timeline:** ประทับเวลาระดับวินาทีทุกกิจกรรมพร้อมชื่อผู้ปฏิบัติงาน
- **ปุ่มคัดลอกลง HIS:** ฟอร์แมตข้อความเป็น Nursing Note / Doctor Note ตามมาตรฐาน SOAP พร้อมกดวาง (Ctrl+V) ลงในโปรแกรม HOSxP ได้ทันที 100%
- **Export Report Modal:** สรุปสถิติประจำกะ, อัตราความสำเร็จของ Bundle, ดาวน์โหลด CSV และพิมพ์ PDF

## บทที่ 10: แดชบอร์ดสรุปสถิติเคสผู้ป่วยที่รักษาแล้ว

- การ์ด KPI 5 ด้าน: ผู้ป่วยทั้งหมด, เสี่ยงสูง, รักษาเสร็จ, Rule Out, Compliance Rate %
- แถบสถิติย้อนหลัง 7 วัน และปฏิทินเลือกวันที่ (Date Picker)
- **In-Dashboard Timeline Modal:** เปิดดูประวัติการรักษาละเอียดของผู้ป่วยในอดีตได้ทันทีในแดชบอร์ด
- ส่งออกประวัติเคสที่รักษาแล้วเป็นไฟล์ CSV

## บทที่ 11: ศูนย์ตรวจสอบเหตุการณ์ระบบและสถานะฐานข้อมูล

- เข้าใช้งานผ่านปุ่ม **"📋 Logs ระบบ"** บน Header Bar
- ฐานข้อมูล SQLite `backend/data/timestamp_logs.db` บันทึกเหตุการณ์ระดับวินาที
- 4 เหตุการณ์สำคัญ:
  1. `connection_lost`: การขาดการเชื่อมต่อ HOSxP MySQL
  2. `connection_restored`: กู้คืนการเชื่อมต่อสำเร็จ
  3. `reconnect_audit_clean` vs `reconnect_audit_diff`: ตรวจสอบความถูกต้องของสัญญาณชีพระหว่างช่วงระบบหลุด
  4. `vitals_modified`: รายละเอียดค่าสัญญาณชีพที่ถูกแก้ไขใน HOSxP
- ตัวกรอง ALL / ERROR / WARNING / NOTE, ช่องค้นหาข้อความ, สวิตช์ Auto-Refresh (ทุก 3 วินาที)

## บทที่ 12: ระบบจัดการสำหรับ IT Admin และชุดทดสอบ

ศูนย์ควบคุมระบบ IT Admin Suite (`/admin`) ประกอบด้วย 5 โมดูล:
1. **Database Failover Tester:** ตรวจสอบ Connection Pool, วัด Latency, ปุ่มสั่งตัด/ต่อ MySQL จริง (`/api/admin/disconnect-db`, `/api/admin/reconnect-db`)
2. **Patient Simulator:** สร้างผู้ป่วยจำลอง, สุ่ม HN, พรีเซ็ตทางคลินิก (Severe, Medium, Normal, Incomplete), พรีวิว Live NEWS, ส่งเคสเข้าคิวทดสอบ
3. **User Management:** รายชื่อบุคลากร, ปิดใช้งานบัญชี (Deactivate), ลงทะเบียนผู้ใช้งานใหม่
4. **Dashboard Cleaner:** ล้างแคชผู้ป่วย พร้อมกลไก **Safe Sepsis Guard** ป้องกันการล้างเคสที่กำลังนับเวลา 60 นาทีอยู่
5. **Alert Simulator:** จำลองยิง Single Alert, Multi-Alert Queue (3 เคส), ทดสอบนับถอยหลัง, ทดสอบเสียงไซเรน

## บทที่ 14: การแก้ไขปัญหาเบื้องต้นและคำถามที่พบบ่อย

### การแก้ไขปัญหาเบื้องต้น (Troubleshooting)
- **เสียงไซเรนไม่ดัง:** ตรวจสอบไอคอนลำโพงบน Header หรือคลิกที่หน้าจอเพื่อปลดล็อก Autoplay Policy
- **ปุ่มยืนยัน Sepsis กดไม่ได้:** สิทธิ์เฉพาะของแพทย์เวร กรุณาให้แพทย์ล็อกอินด้วยสิทธิ์ Doctor
- **แถบนับเวลาติดลบ:** การบริหารยาเกิน 60 นาที ให้รีบรายงานแพทย์และเร่งรัดการบริหารยาโดยด่วน
- **ฐานข้อมูลหลุด (Connection Red):** ระบบจะสลับเข้าสู่โหมดแคชสำรอง ให้ติดต่อ IT เพื่อตรวจสอบเครือข่าย
